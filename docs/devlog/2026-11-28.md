# Tag 1: Vom Playdate-Client zum Always-on-Agenten

Angefangen hat es mit einer einfachen Frage: Kann ich Claude Code, das ich sonst im Terminal benutze, auch von unterwegs bedienen – per Sprache, von einem kleinen Gerät ohne Tastatur? Am Ende des Tages stand das Konzept für etwas deutlich Größeres.

## Die Ausgangslage

Im Repo lag schon ein Entwurf: Der Playdate, eine kleine Handheld-Konsole mit Kurbel, nimmt Sprache auf und schickt sie an einen Server. Dort wird sie in Text umgewandelt und an einen Claude-Agenten weitergegeben. Die Antwort kommt als kleine Schwarz-Weiß-Karte zurück aufs Display.

## Was wir uns überlegt haben

**Wo läuft der Agent?** Ein alter Raspberry Pi 2 ist zu schwach. Eine kleine Cloud-VM bei Azure dagegen reicht völlig, denn die eigentliche Rechenarbeit passiert ohnehin bei Anthropic. Aufgesetzt wird sie mit Pulumi, also als Code statt per Klick.

**Wie wird Sprache zu Text?** Lokal mit Whisper oder über die Voxtral-API von Mistral. Voxtral kostet rund 24 Cent pro Stunde Audio. Das ist so günstig, dass sich ein eigener GPU-Server nicht lohnt. Im Projekt bleibt beides austauschbar.

**Darf der Agent rund um die Uhr laufen?** Ja, mit dem eigenen Claude-Abo auf der eigenen Maschine. Garantiert ist das aber nicht, denn das Abo hat Nutzungsgrenzen. Deshalb arbeitet der Agent nur, wenn es etwas zu tun gibt. Nachts geht er den Tag durch, räumt sein Gedächtnis auf und plant den nächsten Tag. Ist das Wochenkontingent verbraucht, wartet er einfach.

**Ideen abladen statt sofort antworten.** Das Wichtigste ist, dass keine Idee verloren geht. Alles landet zuerst in einer Warteschlange und wird sofort bestätigt. Der Agent arbeitet es dann in Ruhe und gebündelt ab. Kafka dafür wäre mit Kanonen auf Spatzen geschossen, für den Anfang reicht eine kleine Datenbank.

**Werkzeuge nur über einen Türsteher.** Der Agent bekommt keine eigenen Zugänge zu Mail, Kalender oder GitHub. Ein „Rechte- und Tool-Broker“ hält alle Passwörter und entscheidet pro Werkzeug: erlaubt, verboten oder nur nach Rückfrage.

## Aus einem Client wird ein System

Der Playdate ist jetzt nur noch ein Gerät von mehreren. Ein Web-Dashboard kann alles. Daneben gibt es sehr eingeschränkte Geräte: den Playdate, später ein E-Ink-Display und die Smart Glasses Even Realities G1, die sich über das offene Betriebssystem MentraOS ansprechen lassen. Der Agent beschreibt seine Antworten einmal geräteunabhängig, und kleine Adapter machen daraus eine Karte, eine Webseite oder drei Zeilen Text für die Brille. Der Name des Ganzen: **Pocket Concierge**.

## Die wichtigste Entscheidung

Statt erst alles zu bauen, kommt zuerst der Agent in die Cloud. Claude Code hat dafür eine Funktion namens Remote Control: Die Sitzung läuft auf der VM, gesteuert wird sie über die Claude-App auf dem Handy, auf Wunsch per Diktat. Ab dann baut der Agent den Rest seines eigenen Systems mit.

## Ein Concierge und mehrere Rollen

Am Abend kam noch eine Frage dazu: Wie hält man verschiedene Rollen sauber auseinander, etwa einen Agenten fürs Wissen und einen fürs Bauen? Die Antwort: nicht eine Sitzung, die zwischen Rollen hin- und herspringt, sondern eine eigene Sitzung pro Rolle, jede in ihrem eigenen Ordner mit eigenen Regeln. Vorne steht ein Concierge, mit dem man spricht. Er ordnet das Gesagte und legt den anderen Rollen Aufträge in ihre Inbox, wie Zettel in ein Postfach. Startet die VM neu, kommen alle Sitzungen automatisch zurück.

## Vom Konzept zum Code

Zum Schluss wurde es konkret. Statt Azure wird es zunächst ein kleiner Server bei Hetzner, für etwa ein Viertel der Kosten. Angelegt wird er per Knopfdruck über GitHub. Weil das Repo öffentlich ist, stehen alle persönlichen Werte – IP-Adressen, Schlüssel, private Repos – nur in den geschützten Einstellungen von GitHub, nicht im Code. Ein kleiner Wächter auf dem Server merkt, wenn neue Aufträge in einer Inbox liegen, und weckt die zuständige Rolle. Ist das Abo-Kontingent verbraucht, pausiert er, bis es wieder Kontingent gibt.

Und die Reihenfolge danach steht: Bevor der Playdate drankommt, baut der Agent eine Webseite mit einem kleinen Display in Playdate-Größe. Dort lässt sich ausprobieren, wie aus „Ich muss noch die Spülmaschine ausräumen“ eine Tageskarte mit To-dos zum Abhaken wird.

## Der erste echte Server

Am Nachmittag lief der Server tatsächlich, mit zwei Stolpersteinen: Hetzner markiert das Root-Passwort als abgelaufen, und daran scheiterte der Benutzerwechsel im Einrichtungsskript. Und statt sich mit wechselnden IP-Adressen herumzuschlagen, ist der Server jetzt nur noch über Tailscale erreichbar, ein privates Netz für die eigenen Geräte, sogar mit einem Terminal im Browser. Außerdem gibt es jetzt feste Rollentypen: eine Bau-Rolle, die Code-Projekte in mehreren Repos betreut, und eine Wissens-Rolle für Notizen. Wie sie heißen, entscheidet jeder selbst.
